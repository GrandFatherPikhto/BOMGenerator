# BOM Generator (MERN)

Личный однопользовательский веб-инструмент, превращающий **CSV-экспорты BOM из
KiCad** в рабочую таблицу закупок: платы, продавцы, редактируемые правила
категоризации и «Общие закупки». Реализован на стеке MERN (MongoDB, Express,
React, Node).

Это самостоятельный проект. Из исходного Python-инструмента
([`python/bom_merge.py`](python/bom_merge.py)) перенесены **только алгоритмы
разбора номинала и категоризации**; всё остальное написано заново. Исходные
материалы — в [`techdocs/design.md`](techdocs/design.md) и
[`techdocs/plan-2026-09-27.md`](techdocs/plan-2026-09-27.md).

## Возможности

- **Импорт и реимпорт** CSV из KiCad. Ключ реимпорта — имя файла: тот же файл
  обновляет уже существующую плату, обновляя количества и **сохраняя** введённые
  руками продавца/«Общие»/доставку, удаляя пропавшие строки и добавляя новые
  (API возвращает `{added, updated, removed}`).
- **Платы**: у каждой платы свой независимый набор строк и своё количество
  («Плат в изделии», по умолчанию 1).
- **Редактируемые категории разбора** (`ParseCategory`) в базе: режимы
  `prefix`/`regex` отдельно для `Reference` и `Value`, подкатегории по
  `footprintContains`, сортировка. Правка категории сразу видна на всех платах,
  без перезапуска и миграции данных.
- **Продавцы** (`Seller`): количество в упаковке, цена упаковки, URL, описание.
- **Импорт продавцов** из CSV или Excel (с выбором листа). Сопоставление по URL:
  существующему обновляется только название/URL (упаковка, цена, доставка,
  категория и описание не трогаются); новый создаётся со всеми колонками файла.
- **Расчётные колонки** (`totalQty`, `packs`, `cost`) сервер отдаёт готовыми,
  в строках они не хранятся.
- **Общие закупки**: виртуальная агрегация всех строк с галочкой «Общие» по всем
  платам (с учётом количества плат), режимы `merged` и `by_board`.
  Продавец/доставка, заданные здесь, переживают реимпорт.
- **«Докупить»**: служебная плата для позиций, покупаемых вне плат.
- Все значения вводятся и считаются на сервере — формул Excel нет.

## Требования

- **Node.js v24.21.0** (через `nvm`; есть [``.nvmrc`](.nvmrc)):
  ```sh
  nvm install && nvm use
  ```
- **MongoDB 8.x**, запущенная локально:
  ```sh
  sudo systemctl start mongod   # и при желании: sudo systemctl enable mongod
  ```

## Быстрый старт

```sh
nvm use
cp .env.example .env            # при необходимости поправьте MONGODB_URI
npm install
npm run dev
```

`npm run dev` поднимает API на `http://127.0.0.1:3000` и Vite-сервер на
`http://localhost:5173` (клиент проксирует `/api` к API). Откройте адрес Vite в
браузере.

При первом старте сервер добавляет категории по умолчанию (перенесены из
Python-проекта) и создаёт служебную плату «Докупить».

## Экраны

- **Платы** — список плат, диалог импорта (выбор файла и drag-and-drop, имя
  платы, переключатели DNP / Exclude from BOM), создание/удаление.
- **Экран платы** — таблица с жирными блоками категорий и подкатегорий,
  инлайн-выпадашка продавца, чекбокс «Общие», поле «Доставка», расчётные колонки
  и строка «Итого» (позиции «Общие» в неё не входят).
- **Общие закупки** — та же таблица с переключателем `merged` / `by_board`.
- **Докупить** — служебная плата: добавление/правка/удаление ручных позиций.
- **Продавцы** — CRUD-таблица и импорт из CSV/Excel (выбор листа для XLSX,
  показ сводки и предупреждений после импорта).
- **Категории разбора** — CRUD-таблица; ошибки regex показываются прямо в форме.
- **Настройки** — категория/сортировка по умолчанию, подпись подкатегории,
  флаги DNP/BOM.

## Как это работает

1. Клиент обращается к Express API; модели Mongoose хранят данные в MongoDB.
2. `POST /api/boards/import` разбирает CSV (колонки по именам, терпимо к
   UTF-8/BOM), фильтрует DNP / Exclude from BOM, агрегирует строки по
   `matchKey`, затем обновляет/создаёт их и удаляет пропавшие.
3. `matchKey` — нормализованный номинал плюс нормализованный корпус; он
   используется и для реимпорта, и для группировки в «Общих закупках».
4. При выводе платы категории пересчитываются по текущим `ParseCategory`,
   строки группируются в блоки, сортируются, а `totalQty`, `packs` и `cost`
   считаются на лету.

Диаграммы — в [`docs/architecture.md`](docs/architecture.md).

## Тесты

```sh
npm test
```

- Юнит-тесты общего модуля (`tests/shared`) покрывают парсер и категоризатор,
  включая векторы из ТЗ (`"4K7" == "4.7K"` по ключу, `"2.2 uF" != "2.2 uF 25V"`,
  нераспознанные партномера, regex-режимы, отклонение невалидного regex).
- Интеграционные тесты API (`tests/api`) работают с реальной локальной MongoDB и
  проверяют реимпорт, сохранение ручных полей, «Общие закупки» и «Докупить».

## Решения и `TODO(confirm)`

1. **«Докупить»** — служебная `Board` без `sourceFile` (уникальный индекс
   `sparse`). Создаётся автоматически, не удаляется, участвует в «Общих
   закупках» наравне с платами.
2. **DNP / Exclude from BOM** — глобальные значения `Settings` плюс переключатели
   в диалоге импорта (по умолчанию оба исключают).
3. **Расчётные поля** (`totalQty`, `packs`, `cost`) считаются при каждом запросе
   и не хранятся.
4. **`matchKey`** не зависит от категории: распознанные значения
   нормализуются (единица + величина + хвост), нераспознанные хранят написание.
   Это необходимо для критерия 4 (`"4K7"` и `"4.7K"` дают один ключ) и
   сохраняет ручные значения при правке категорий.
5. **Таблицы клиента** построены на MUI (своя блочная отрисовка), а не на
   библиотеке таблиц — важно поведение, а не конкретный пакет.
6. **Тесты используют локальную MongoDB** (создаётся и удаляется отдельная БД на
   процесс) вместо `mongodb-memory-server`.

## Известные ограничения

- Экспорт обратно в Excel/CSV пока вне рамок.
- Аутентификации нет (инструмент для одного пользователя в локальной сети).
- Ячейка `Footprint` с несколькими корпусами остаётся одной строкой (KiCad
  отдаёт агрегированное `Qty`, разделить его нельзя).
- «Голые» сокращения ёмкости вроде `100n` читаются как `100 nΩ` (как в Python).
- Формулы Excel не генерируются: все деньги считаются на сервере.
